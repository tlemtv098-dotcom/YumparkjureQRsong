# สคริปต์ซ้อมสาธิต — ร้านยำปากเจ่อ (Jukebox)

> เป้าหมาย: เดินครบ 10 ข้อเกณฑ์ใน ~12 นาที + เก็บโบนัสระหว่างทาง
> URL: `https://yumpakjure.onrender.com/`
> บัญชีสาธิต: `admin` / `staff` / `customer` — รหัส `12345678` ทั้งหมด

## ก่อนเริ่ม 5 นาที (ห้ามลืม)

- [ ] เปิดหน้าเว็บ + หน้า dashboard ทิ้งไว้ในแท็บ (กัน Render cold start ~60 วิ)
- [ ] เปิดสไลด์ `ไฟล์นำเสนอ.pptx` พร้อม
- [ ] เตรียมไฟล์รูป 1 รูปไว้เปลี่ยน avatar (ข้อ 4)
- [ ] อย่ากดค้นหาเพลงพร่ำเพรื่อก่อนสาธิต (เปลืองโควตา YouTube — วันละ 300 ครั้งรวม 3 key)

---

## ขั้น 1 — เปิด + สมัครสมาชิก (ข้อ 1, ~1 นาที)

1. เปิดหน้าแรก → ชี้ QR (`/qr.png`) อธิบาย: ลูกค้าสแกนแล้วขอเพลงได้โดยไม่ต้องล็อกอิน
2. กดสมัครสมาชิก → กรอกฟอร์ม → เข้าระบบอัตโนมัติ
3. กดออก → เข้าสู่ระบบใหม่ → พูด: "ใช้ Authentication ของ Django ทั้งหมด ไม่ได้เขียนระบบล็อกอินเอง"

**ประโยคเก็บคะแนน:** "Register Login Logout ครบ มี 3 ระดับ: admin จัดการทุกอย่าง staff จัดการเพลง customer ขอเพลงได้อย่างเดียว"

## ขั้น 2 — ขอเพลงมุมลูกค้า (ข้อ 3, ~1.5 นาที)

1. หน้า `/request/` พิมพ์ชื่อเพลงไทย → กดค้นหา → ผลขึ้นพร้อมปุ่มขอเพลง
2. กดขอเพลง → ขึ้นคิวทันที ชื่อคนขอแสดงในแถว
3. เปิดหน้า player ให้ดูเพลงเล่น + ข้ามเพลง

**ประโยคเก็บคะแนน:** "ค้นหาจาก YouTube API ถ้าโควตาหมดจะ fallback ไปค้นเพลงในฐานข้อมูลตัวเอง ไม่พัง"

## ขั้น 3 — เข้า admin จัดการผู้ใช้ (ข้อ 1+2, ~2 นาที)

1. ล็อกอิน `admin` → เปิด จัดการผู้ใช้
2. **Create:** เพิ่มผู้ใช้ใหม่ ตั้ง role staff
3. **Read:** เปิดหน้า edit ให้ดู — อธิบายว่าฟอร์มนี้แสดงข้อมูลทั้งหมด ทำหน้าที่เป็นหน้ารายละเอียดด้วย
4. **Update:** เปลี่ยน role → บันทึก
5. **Delete:** กดลบ → ชี้ popup "ยืนยันการลบผู้ใช้นี้? จะไม่สามารถกู้คืนได้" → ยืนยัน
6. ลองเข้า `/management/users/` ด้วยบัญชี customer ให้ดูว่าโดนเด้ง (จำกัดสิทธิ์จริง)

**ประโยคเก็บคะแนน:** "CRUD ครบบนฐานข้อมูลจริง มีหน้ารายละเอียดคือฟอร์มนี้ และมีการยืนยันก่อนลบทุกครั้ง"

## ขั้น 4 — จัดการแนวเพลง + ค้น + แบ่งหน้า (ข้อ 2+3+5, ~1.5 นาที)

1. เปิดจัดการแนวเพลง → พิมพ์ค้นในช่องค้น → ผลกรองทันที (ค้น + Pagination ทำงานร่วมกัน)
2. กดหน้าถัดไป/หน้าสุดท้าย → ชี้เลข "หน้า 1 / N"
3. เพิ่มแนวเพลงใหม่ → แก้ไข → ลบ (ย้ำ popup ยืนยันอีกครั้ง)

## ขั้น 5 — อัปโหลดรูป (ข้อ 4, ~1 นาที)

1. เปิดโปรไฟล์ → อัปโหลด avatar ใหม่ → รูปเปลี่ยนทันที
2. พูด: "ไฟล์เก็บใน `media/` เสิร์ฟผ่าน view ที่กัน path traversal — เข้าถึงไฟล์นอกโฟลเดอร์ไม่ได้"

## ขั้น 6 — Dashboard + Export (โบนัส, ~1.5 นาที)

1. เปิด dashboard → ชี้กราฟ 4 ตัว (แนวนอน/เส้น/เพลงฮิต/โดนัท) "ดึงจากฐานข้อมูลจริง ไม่ใช่ตัวเลขแต่ง"
2. กดส่งออก CSV 2 ไฟล์ → เปิดใน Excel ให้ดูภาษาไทยไม่เพี้ยน (เพราะ `utf-8-sig`)
3. พูดโบนัส: "มี REST API เกือบ 20 endpoint, เชื่อม YouTube API ภายนอก, ใช้ AJAX ทั้งเว็บไม่โหลดหน้าใหม่"

## ขั้น 7 — อธิบาย Model (ข้อ 6+10, ~2 นาที) — ส่วนสำคัญที่สุด

เปิด `music/models.py` แล้วพูดทีละตัว:

- `Profile.user = OneToOneField(User)` — คนละ 1 โปรไฟล์ เก็บ role
- `Playlist.user = ForeignKey(User)` — เพลย์ลิสต์ของใครของมัน ลบ user แล้วเพลย์ลิสต์หายตาม (`on_delete=CASCADE`)
- `Playlist.genres/tags = ManyToManyField` — 1 เพลย์ลิสต์มีได้หลายแนว 1 แนวอยู่ได้หลายเพลย์ลิสต์
- `PlaylistSong` — ตารางกลางเก็บลำดับเพลง (`position`) + กันเพลงซ้ำ (`unique_together`)
- `SongQueue` — คิวเพลง มี `requested_by` + `client_id` จำเครื่องลูกค้าโดยไม่ต้องล็อกอิน

## ขั้น 8 — เทสต์ + ความปลอดภัย (โบนัส, ~1 นาที)

1. พูด: "เขียนเทสต์ 386 เคส 25 โมดูล รันผ่านทั้งหมด"
2. เปิดไฟล์ `tests_xss.py` ชี้บรรทัดเดียว: input มี `<script>` ถูก strip ทิ้ง
3. พูด: "มี rate limit กันยิง API รัว, CSRF ทุกฟอร์ม, รหัสผ่าน hash ด้วย Django, secret อยู่ใน Environment ไม่ hardcode"

## ขั้น 9 — รายงาน (ข้อ 9, ~30 วิ)

เปิด PDF: "รายงาน 29 หน้า — บทนำ ขอบเขต Use Case ออกแบบ Model ความสัมพันธ์ ภาพหน้าจอ ผลทดสอบ ปัญหาและข้อเสนอแนะ"

## ปิด (~30 วิ)

"ระบบรันบน Render + ฐานข้อมูล Neon ข้อมูลไม่หายตอน deploy — เปิดใช้งานจริงได้เลยครับ"

## คำถามที่อาจโดนถาม + คำตอบสั้น

| คำถาม | ตอบ |
|---|---|
| ทำไมใช้ Neon ไม่ใช้ SQLite? | SQLite บน Render หายทุกครั้งที่ deploy — Neon เป็น Postgres จริง ข้อมูลอยู่ถาวร |
| `client_id` ใน localStorage คืออะไร? | จำเครื่องลูกค้าโดยไม่ต้องล็อกอิน เพลงที่ขอผูกกับเครื่องนั้น |
| `role_required` ทำงานยังไง? | decorator เช็ค `profile.role` ก่อนเข้า view ไม่ผ่านเด้งออก |
| ใช้ AI ช่วยแค่ไหน? | ช่วยเขียน+ตรวจโค้ด แต่ทุกบรรทัดอ่านเอง เทสต์เอง แก้เองได้ (เกณฑ์บังคับข้อนี้) |
| โควตา YouTube หมดทำไง? | fallback ค้นเพลงในฐานข้อมูลตัวเอง + แคชเพลงแนะนำ 15 นาที |
| ทำไมลบแล้วกู้ไม่ได้? | `on_delete=CASCADE` ลบจริง ไม่ใช่ soft delete — เลยต้องมี popup ยืนยันก่อนเสมอ |
| ช้า 60 วิตอนเปิดครั้งแรก? | Render แผนฟรีหลับเมื่อไม่มีคนเข้า ครั้งต่อไปเร็วปกติ |

## แผนสำรองถ้าพังกลางสาธิต

- เน็ต/YouTube ล่ม → ใช้เพลงแนะนำ + fallback DB (เตรียมไว้แล้ว)
- ลืมรหัส → `admin` / `12345678`
- กราฟว่าง → อธิบายว่ากราฟนับจากข้อมูลจริง ไม่มีข้อมูลก็ไม่แต่งตัวเลข
